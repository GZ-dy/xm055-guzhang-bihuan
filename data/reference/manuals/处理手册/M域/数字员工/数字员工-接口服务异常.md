## 适用范围与故障判定

### 适用范围

遇到以下任一现象，进入本手册流程处理：

- 智能小7打开异常
- 智能小7提报障单异常
- 数字员工 出现与 接口服务异常 相关的重复性故障现象。
- 页面、接口、任务或日志表现异常，需要先确认影响范围再执行恢复。
- 恢复后必须验证业务入口、关键日志和监控告警均已恢复。

### 判定规则

| 如果看到 | 先做什么 | 判断结论 |
|----------|----------|----------|
| 页面或接口不可用 | 确认进程、端口和最近日志 | 先收敛到应用侧还是依赖侧 |
| 进程存在但页面打不开或请求超时 | 记录 PID，必要时保留线程现场，再 kill 旧进程并重启 | 按服务假活处理，不能只看进程存活 |
| 恢复后仍有告警 | 回查页面、接口、日志和监控 | 确认是否是假恢复或依赖未恢复 |

## 标准处置流程

1. 记录告警时间、故障入口、受影响业务和当前监控状态。
2. 确认服务进程、端口监听、资源水位和最近日志关键字。
3. 按故障边界通知运维、厂商、开发或 DBA 介入处理。
4. 执行恢复动作后回查页面、接口、任务和日志。
5. 若短时间复发，保留现场并升级根因分析，不只重复重启。

## 关键检查命令

以下命令已按本故障场景去重整理；每条命令先说明用途，执行前按实际主机、路径、权限和变更流程确认。

### 查看相关进程

确认相关服务进程是否存活、是否存在重复或僵死进程。

```bash
ps -ef | grep -Ei "service" | grep -v grep
```
### 查看服务状态

若服务由 systemd 管理，可直接确认当前状态与最近报错。

```bash
systemctl status service --no-pager
```
### 查看最近日志

先看近 200 行日志，快速确认报错关键字与时间点。

```bash
tail -n 200 /var/log/service.log
```
### 查看系统资源快照

先建立现场快照，便于判断是服务问题还是环境问题。

```bash
uptime && free -h && df -h
```
### 检查关键日志关键字

按实际日志路径替换，快速搜集错误、超时、异常退出信息。

```bash
grep -Ei "error|exception|timeout|oom|fail" /var/log/service.log | tail -n 50
```

## 协同分工与通知口径

### 通知口径

> 数字员工 出现 接口服务异常，当前已按手册确认故障对象为 数字员工 应用节点。请对应责任团队优先处理主故障点，运维侧同步保留现场并完成页面、接口、任务和监控恢复验证。

### 谁负责什么

| 角色 | 负责范围 | 处置动作 |
|------|----------|----------|
| 一线运维 | 告警确认、现场操作、恢复验证 | 执行标准处置流程并记录结果 |
| 系统维护 / 厂商 | 应用服务、脚本、配置和程序逻辑 | 恢复服务并定位反复故障根因 |
| DBA / 平台支撑 | 数据库、中间件、主机和网络依赖 | 在扩展验证异常时介入处理 |

## 恢复验证清单

完成恢复动作后，按以下顺序验证：

1. 数字员工 关键页面或入口可正常访问。
2. 相关告警已消除或回落到正常阈值。
3. 最近日志不再持续出现同类错误关键字。
4. 服务进程、端口和核心接口均恢复正常。
5. 恢复后至少完成一次关键业务路径验证。

## 根因与预防

### 根因判断

- 直接根因：接口服务异常 导致 数字员工 关键业务路径异常。
- 应用表现：页面、接口、任务或日志链路异常，需要结合现场进一步定位。
- 处置边界：先按本手册主故障点恢复，再扩展检查依赖链路。

### 长期预防

- 补充进程、端口、错误率、接口耗时和关键日志监控。
- 固化标准恢复动作、升级边界和恢复验证要求。
- 对重复故障输出根因修复计划，不只依赖人工重启。
