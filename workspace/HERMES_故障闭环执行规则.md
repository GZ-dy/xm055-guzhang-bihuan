# Hermes 故障闭环执行规则

下面整份内容可直接交给 Hermes 使用。Hermes 应调用本项目现有代码，不要自行重写 Word、Excel、飞书或邮件逻辑。

## 1. 任务目标

收到企业微信群里 `@机器人` 后的故障文本时，完成以下唯一闭环：

`解析故障文本 -> 校验 incident_context -> 生成 Word 报告 -> 生成离线 Excel 台账 -> 写入飞书在线表 -> 写入成功后发送邮件 -> 回填邮件状态 -> 返回处理结果`

企业微信只负责接收文本和返回结果。业务处理统一从项目根目录的 `run_closed_loop.py` 进入。

## 2. 允许直接使用的输入模板

```text
系统：OPENAPI系统
发生日期：7月15日
故障原因：数据库网络异常
1. 14:20：网格通通知OPENAPI接口故障
2. 14:22：多域维护组排查OPENAPI服务状态
3. 14:25：多域维护组检查数据库网络连通性
4. 14:28：多域维护组重启异常服务并验证接口
5. 14:35：网格通验证业务恢复，系统恢复正常
```

用户不需要填写标题、影响范围、处理人员、处理组、解决方案、闭环结论或后续措施。能由现有代码和正式联系人表确定的字段，由程序补齐。

## 3. 文本识别规则

1. `系统` 保留用户填写的系统名称，例如 `OPENAPI系统`。
2. `发生日期` 支持 `7月15日` 或 `2026年7月15日`。没有年份时使用运行当年；2026 年运行即按 2026 年处理。
3. 时间线必须采用 `序号 + 时间 + 实际动作`，例如 `1. 14:20：...`。每个时间点继承 `发生日期`，不得另行猜测日期。
4. 第一条时间线作为故障发生时间；最后一条只有同时包含“验证、恢复、正常/通过/成功”语义时，才可作为恢复时间和恢复验证依据。
5. 中间时间线按用户原文保留，作为真实处理过程。不得合并掉用户提供的时间点。
6. `故障原因` 按原文使用。允许润色句子，但不得改变原因、操作主体或技术事实。
7. 解决方案只可从用户写明的实际动作中提取，例如重启、切换、修复、回滚、清理、扩容、重连。
8. 可以补充连贯描述、影响说明、复盘文字和后续措施，但只能依据系统、故障原因和实际时间线生成，不得增加新的时间、人员、操作、故障范围或验证结果。
9. 禁止输出 `待补充`、`待确认`、`待后续补充` 等占位内容。关键事实确实不足时返回 `need_review`，不得编造后继续写表或发邮件。
10. `处理组` 在报告和邮件中统一写 `多域维护组`。在线表 `处理人员` 必须从 `data/reference/contacts/multi_domain_contacts.json` 匹配具体中文姓名，不能写部门或小组名称。
11. 手册匹配按系统名和故障原因执行；`OPENAPI系统` 应按 `OPENAPI` 别名匹配。

## 4. 两步执行规则

第一步只构建并校验事实源：

```powershell
python -B run_closed_loop.py --text "<收到的完整故障文本>" --case-id "<唯一case_id>" --incident-context-only
```

只有返回 `status=validated` 且 `missing_fields` 为空，才执行第二步。

第二步正式闭环：

```powershell
python -B run_closed_loop.py --incident-context "work/cases/<case_id>/incident_context.json" --apply --send-mail --confirm-live-write LIVE-WRITE
```

正式执行前，Hermes 运行机器必须自行配置飞书、SMTP 和以下生产闸门；任何密钥不得写进本文件、聊天记录或代码：

```text
FAULT_AUTO_SEND_ON_VALIDATED=1
FAULT_CONFIRM_LIVE_WRITE=LIVE-WRITE
FAULT_PROD_CASE_TOKEN=<非空生产令牌>
```

## 5. 强制顺序与失败规则

1. `incident_context` 是唯一可信事实源，不得从旧报告、旧台账或历史输出反推。
2. Word 报告和离线 Excel 生成成功后，才进入飞书在线表写入。
3. 飞书写入或读回校验失败时，必须停止；不得继续发送邮件。
4. 飞书写入成功后发送邮件，附件至少包含本次 Word 报告和离线 Excel 台账。
5. 邮件发送成功后回填 `邮件闭环状态=已发送`；失败则保留失败原因，不得伪报成功。
6. 重复 case 命中且邮件状态已发送时，不重复发信。
7. 所有 dry-run 只生成本地产物和邮件预览，禁止写飞书、禁止真实发信。

## 6. 返回给群里的结果

成功时返回：

```text
故障闭环处理完成
系统：<系统名称>
发生时间：<第一条时间>
恢复时间：<最后一条验证恢复时间>
报告：已生成
在线表：写入成功
邮件：发送成功
case_id：<case_id>
```

失败时必须返回真实阻断步骤和原因，例如：

```text
故障闭环未完成
阻断步骤：飞书在线表写入
原因：<真实错误摘要>
邮件：未发送
case_id：<case_id>
```

不得只回复“处理中”或“成功”，也不得在飞书写入失败时回复邮件已发送。

## 7. 部署边界

- 长连接机器人只能在 Hermes 所在的运行机器上配置和启动。
- 本地 Windows 机器不再保存或使用 `WECHAT_BOT_ID`、`WECHAT_BOT_SECRET`。
- Hermes 若没有企业微信长连接/Webhook、飞书配置或 SMTP 配置，仅接收本规则文件并不能自动获得这些权限；必须在 Hermes 运行环境完成对应接入。
- 不修改 `data/templates/official/`，继续复用项目已有正式 Word/Excel 模板。
