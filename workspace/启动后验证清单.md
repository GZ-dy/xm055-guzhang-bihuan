# 飞书 record 验证清单 (启动后你看哪些字段算成功)

## 1. 群回执检查 (在企业微信群里直接看)

bot @你 触发后应在群里**自动回复 6 字段**:

```
1) 收到消息：是
2) case_id：wecom_20260710_xxxxxx_xxxxxxxx
3) 校验：通过 (含所有产物)
4) 报告路径：C:\fault-closed-loop\outputs\reports\<case_id>\BOMC7月10日故障报告.docx
5) 台账路径：C:\fault-closed-loop\outputs\ledger\<case_id>\【2026】多域系统故障记录表_<...>.xlsx
6) 邮件预览：C:\fault-closed-loop\outputs\mail\<case_id>\mail_preview.json
```

**如果**:
- 1) 收到消息：否 → bot 没收到, 网络/启动问题
- 3) 校验：需补充 (有缺字段) → 故障信息太简略, 补字段重发
- 3) 校验：失败 → 异常, 看 PowerShell 窗口日志
- 4) 报告路径：(未生成) → 缺字段, 跟 3 一样

## 2. 飞书 record 检查 (在飞书后台看你之前给的 bitable_app_token / table_id 表)

**新增 record 应该有以下字段** (按你之前 75 条 record 模式):

| 字段 | 预期值 |
|---|---|
| 序号 | 76 (上一条 +1) |
| 业务中断时间 | 2026-07-10 14:23 (发生时间) |
| 业务恢复时间 | 2026-07-10 14:33 (恢复时间) |
| 故障描述 | 含 "HTTP 500 内部服务器错误" 或具体异常现象 |
| 故障现象 | 影响范围文字 (客户无法登录...) |
| 业务影响 | 量化 (影响人数, 持续时长) |
| 处理过程 | 5 个时间戳 (14:23 / 14:25 / 14:28 / 14:30 / 14:33) |
| 恢复手段 | 重启 cas 服务进程 |
| 处理人 | 梁铭图 (写全名, 不是工号) |
| 闭环结论 | 系统已恢复并完成验证 |
| 磐基 | 是 (如果该 case 涉及磐基) |
| 是否已提故障工单号 | 否 (本地值班版默认不开工单) |
| 邮件状态 | 已发送 (开了 SMTP env 时) |

**如果 record 没新增**:
- 看 PowerShell 窗口, 应有 `event: "fault_handled"` 日志
- 看 `outputs/ledger/<case_id>/record_payload.json` 是否生成
- 看 `outputs/ledger/<case_id>/` 是否有 `【2026】多域系统故障记录表_*.xlsx` 离线表
- 飞书写失败会有 errcode, 常见:
  - 99991663: app_id/app_secret 错
  - 99991661: bitable_app_token/table_id 错
  - 99991400: 字段名/类型不匹配
  - 99992321: 权限不足

## 3. 邮件检查 (在收件人邮箱看)

**收件人应该收到 1 封邮件**:
- 发件人: 你设的 FAULT_SMTP_USER (例: ops@163.com)
- 主题: 跟飞书 record 序号对应, 或 case_id
- 附件: report.docx (报告) + 离线表.xlsx (台账)
- 正文: 简要总结 + 报告路径 + 闭环结论

**如果邮件没收到**:
- 看 `outputs/mail/<case_id>/mail_preview.json` 是否生成
- 看 PowerShell 窗口 SMTP 错误
- 163 smtp 常见错:
  - 553: 授权码错或过期
  - 535: 认证失败
  - 554: 邮件被拒 (内容/收件人)
  - 连接超时: 网络/防火墙

## 4. 本地产物 (在 Windows 文件管理器看)

bot 跑过一次后, `C:\fault-closed-loop\outputs\` 应有 5 个目录:

```
C:\fault-closed-loop\outputs\
├── reports\<case_id>\
│   └── BOMC7月10日故障报告.docx    ← Word 报告
├── ledger\<case_id>\
│   ├── 【2026】多域系统故障记录表_<case_id>.xlsx    ← 离线表
│   ├── record_payload.json                          ← 飞书 record 完整 payload
│   └── execution_plan.json                          ← pipeline 派单计划
├── mail\<case_id>\
│   └── mail_preview.json                            ← 邮件预览
├── manuals\<case_id>\
│   └── manual_match_result.json                     ← 手册匹配结果
└── validation\<case_id>\
    └── validation_result.json                       ← incident_context 校验结果
```

`C:\fault-closed-loop\work\cases\<case_id>\incident_context.json` ← 主数据, 校验后 status=validated
